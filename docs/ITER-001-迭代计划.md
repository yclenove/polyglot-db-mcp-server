# ITER-001: v1.5 迭代计划

> **版本**: v1.4.0 → v1.5.0 | **日期**: 2026-05-05 | **状态**: 待评审

---

## 1. 迭代目标

**在保持现有 73 个工具稳定性的前提下，新增数据脱敏、智能查询建议、查询回放 3 个能力，提升安全合规性、AI 查询质量和调试效率。**

## 3. 影响分析矩阵

### 3.1 数据脱敏模式

| 维度 | 影响范围 | 风险等级 |
|------|---------|---------|
| 代码范围 | 新增 `src/core/data-masking.ts`（正则引擎）、`src/tools/masking.ts`（1 个新工具）、修改 `src/tools/sql.ts` 和 `src/tools/mongo.ts` 的返回值处理 | 中 |
| 数据影响 | 仅对查询结果做内存转换，不修改源数据 | 低 |
| API 影响 | 新增 `data_masking_config` 工具；`sql_query`/`mongo_find` 新增可选 `masking` 参数 | 低 |
| 测试影响 | 新增 ~25 个测试（正则匹配、边界情况、多引擎兼容） | 中 |
| 文档影响 | 新增工具文档、环境变量 `DB_MASKING_RULES` 说明 | 低 |
| 回归风险 | 低。脱敏为纯函数，不影响现有数据流 | 低 |

### 3.2 智能查询建议

| 维度 | 影响范围 | 风险等级 |
|------|---------|---------|
| 代码范围 | 新增 `src/core/query-advisor.ts`（分析引擎）、`src/tools/advisor.ts`（1 个新工具） | 低 |
| 数据影响 | 无。只读分析表结构和执行计划 | 无 |
| API 影响 | 新增 `sql_advise` 工具，接受 SQL 文本，返回优化建议 | 低 |
| 测试影响 | 新增 ~18 个测试（建议准确性、多引擎覆盖） | 中 |
| 文档影响 | 新增工具文档 | 低 |
| 回归风险 | 低。纯分析工具，不修改查询行为 | 低 |

### 3.3 查询回放与对比

| 维度 | 影响范围 | 风险等级 |
|------|---------|---------|
| 代码范围 | 扩展 `src/core/audit.ts`（查询历史存储）、新增 `src/tools/replay.ts`（2 个新工具） | 低 |
| 数据影响 | 内存中保存最近 50 条查询结果快照（可配置） | 低 |
| API 影响 | 新增 `sql_replay` 和 `sql_diff_query` 工具 | 低 |
| 测试影响 | 新增 ~15 个测试（回放准确性、diff 算法） | 低 |
| 文档影响 | 新增工具文档 | 低 |
| 回归风险 | 低。独立模块，不影响现有查询流程 | 低 |

## 4. 风险清单

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| 脱敏正则误匹配（如将合法数字误判为手机号） | 中 | 中 | 支持白名单字段排除；提供 `strict`/`loose` 两种模式 |
| 查询建议依赖表结构元数据，大表分析耗时 | 低 | 低 | 设置分析超时（默认 5s）；缓存表结构信息 |
| 查询结果快照占用内存过多 | 低 | 中 | 限制快照条数（默认 50）和单条大小（默认 10KB） |
| 新增工具导致 MCP 工具列表过长 | 低 | 低 | 合并为 3 个工具，保持工具总数 ≤ 80 |

---

## 5. 回滚方案

| 功能 | 回滚方式 | 影响范围 |
|------|---------|---------|
| 数据脱敏 | 移除 `data_masking_config` 工具注册；`sql_query`/`mongo_find` 的 `masking` 参数忽略 | 脱敏功能不可用，其他功能不受影响 |
| 智能查询建议 | 移除 `sql_advise` 工具注册 | 建议功能不可用，其他功能不受影响 |
| 查询回放 | 移除 `sql_replay`/`sql_diff_query` 工具注册；清理 audit 扩展代码 | 回放功能不可用，审计日志基础功能不受影响 |

> 所有回滚均为移除独立模块注册，无数据库迁移，回滚时间 < 5 分钟。

## 8. 验收标准（Given/When/Then）

### 8.1 数据脱敏模式

| 场景 | Given | When | Then |
|------|-------|------|------|
| 手机号脱敏 | 查询结果包含 `phone: "13812345678"` | 调用 `sql_query` 并启用 masking | 返回 `phone: "138****5678"` |
| 身份证脱敏 | 查询结果包含 `id_card: "110101199001011234"` | 启用 masking | 返回 `id_card: "110101****1234"` |
| 邮箱脱敏 | 查询结果包含 `email: "test@example.com"` | 启用 masking | 返回 `email: "t***@example.com"` |
| 白名单排除 | 配置排除 `phone` 字段 | 启用 masking | `phone` 字段保持原值 |
| 无敏感数据 | 查询结果无敏感字段 | 启用 masking | 返回原值，无性能损耗 |

### 8.2 智能查询建议

| 场景 | Given | When | Then |
|------|-------|------|------|
| 缺失索引建议 | 表 `users` 有 10 万行，`email` 列无索引 | 调用 `sql_advise` 分析 `SELECT * FROM users WHERE email = ?` | 建议"为 email 列创建索引" |
| SELECT * 优化 | 任意表 | 分析 `SELECT * FROM orders` | 建议"指定需要的列名，避免 SELECT *" |
| 无优化空间 | 简单查询已使用索引 | 分析 | 返回"当前查询无明显优化空间" |

### 8.3 查询回放与对比

| 场景 | Given | When | Then |
|------|-------|------|------|
| 查询回放 | 历史记录中有查询 ID `q-001` | 调用 `sql_replay` 指定 ID | 返回与原查询相同的结果 |
| 结果对比 | 两次查询结果行数不同 | 调用 `sql_diff_query` 对比 | 返回差异摘要：新增 X 行、删除 Y 行、修改 Z 行 |
| 无差异 | 两次查询结果相同 | 调用 `sql_diff_query` | 返回"结果一致" |
