# PRD-001: polyglot-db-mcp-server 产品需求文档

> **版本**: v1.4.0 | **日期**: 2026-05-05 | **状态**: 初稿，待确认

---

## 1. 产品概述

**一句话定位**: 面向 AI 助手的多引擎数据库 MCP 服务，一个进程统一管理 MySQL / PostgreSQL / MSSQL / Oracle / MongoDB / Redis 六种后端。

| 核心价值 | 说明 |
|---------|------|
| 多引擎统一 | 6 种数据库引擎通过同一 MCP 协议暴露，AI 助手无需切换工具 |
| 安全可控 | 只读连接、SQL 注入检测、NoSQL 注入防护、凭证脱敏、Redis 危险命令拦截 |
| 生产就绪 | 审计日志、速率限制、查询缓存、Prometheus 指标、事务超时保护 |
| 开发友好 | 从表结构生成 TS 类型、Schema 导出 JSON/DDL、分页查询 |

## 4. P0 功能验收标准（Given/When/Then）

| 功能 | Given | When | Then |
|------|-------|------|------|
| 多引擎查询 | 配置了 MySQL 和 PostgreSQL 连接 | AI 助手调用 `sql_query`，指定不同 `connection_id` | 分别返回对应引擎的查询结果，包含 engine 字段标识 |
| 只读保护 | 连接配置 `readonly: true` | 调用 `sql_execute` 执行 INSERT | 返回错误"该连接为只读"，审计日志记录失败 |
| SQL 注入拦截 | 任意 SQL 连接 | 调用 `sql_query` 传入 `SELECT * FROM users; DROP TABLE users` | 返回错误"仅允许只读语句"，不执行任何 SQL |
| NoSQL 注入拦截 | MongoDB 连接 | `mongo_find` 的 filter 包含 `$where` 操作符 | 返回错误"潜在 NoSQL 注入风险"，不执行查询 |
| 事务原子性 | MySQL 连接，`readonly: false` | 调用 `sql_batch_execute` 执行 3 条 SQL，第 2 条失败 | 前 1 条自动回滚，返回 `success: false` 和失败 SQL 信息 |
| 分页查询 | PostgreSQL 连接有 100 行数据 | `sql_query` 传入 `page: 2, page_size: 20` | 返回第 21-40 行数据，pagination 包含 has_next/has_prev |
| 健康检查 | 配置了 3 个连接 | 调用 `health_check` | 返回每个连接的 status、latency_ms，全部 ok 时整体为 healthy |
| 事务超时 | 事务创建后超过 5 分钟未操作 | 系统自动检测 | 事务自动回滚并从活跃事务列表移除 |

## 5. 非功能需求

| 维度 | 需求 | 配置方式 |
|------|------|---------|
| **性能** | 查询超时 30s，最大返回 100 行（可调），查询缓存 LRU | `DB_QUERY_TIMEOUT`、`DB_MAX_ROWS`、`DB_QUERY_CACHE_SIZE` |
| **安全** | SQL 注入检测（16 种模式）、NoSQL 注入检测、凭证脱敏、Redis 危险命令拦截 | 内置；`REDIS_BLOCKED_COMMANDS` 可自定义 |
| **可用性** | 默认连接 ping 失败退出；非默认连接失败仅告警；事务 5 分钟超时自动回滚 | `DB_TRANSACTION_TIMEOUT_MS`、`DB_SHUTDOWN_TIMEOUT_MS` |
| **可观测** | 结构化日志（JSON/人类可读）、Prometheus 指标、审计日志（最近 1000 条） | `LOG_LEVEL`、`LOG_FORMAT` |
| **限流** | 每连接每秒请求上限 | `DB_RATE_LIMIT_PER_SECOND` |

## 6. 创新提案

| 提案 | 说明 | 预期价值 |
|------|------|---------|
| **智能查询建议** | AI 助手调用 `sql_query` 前，自动分析表结构并建议优化的 WHERE 条件和 JOIN 方式 | 降低 AI 生成低效 SQL 的概率 |
| **自动索引推荐** | 基于 `sql_explain` 执行计划和慢查询日志，自动推荐缺失索引 | 帮助 DBA 快速定位性能瓶颈 |
| **数据脱敏模式** | 新增 `data_masking` 工具，对查询结果中的手机号、身份证、邮箱等字段自动脱敏 | 满足数据合规要求，AI 助手可安全处理敏感数据 |
| **查询回放与对比** | 保存历史查询，支持 `sql_diff_query` 对比两次查询结果差异 | 适合数据迁移验证和回归测试 |
| **跨库关联查询** | 新增 `cross_db_query` 工具，支持在不同引擎的连接间执行关联查询（客户端 JOIN） | 打通异构数据源，减少 AI 助手多次调用 |
