## 本轮已转化

1. MongoDB filter/pipeline 使用共享递归 guard，覆盖数组内嵌 operator。
2. `mongo_aggregate` 拒绝 `$out`/`$merge`，并校验 `$lookup`、`$graphLookup`、`$unionWith` 引用集合。
3. MongoDB driver 在 `find`、`aggregate`、`count` 上应用服务端 `maxTimeMS`。
4. MongoDB JSON 参数支持 canonical Extended JSON，BSON 输出保持 Int64/ObjectId/Decimal128 类型信息。
5. 聚合结果默认 50、最大 500 条，真实数据库矩阵验证 Int64 与写阶段拦截。
6. 六个 SQL 驱动改为有界读取：PostgreSQL `DECLARE/FETCH`、MySQL `sql_select_limit` 加事件流、SQL Server stream/cancel、Oracle `maxRows`、SQLite `iterate()`、DuckDB chunk reader。
7. 没有直接复制 DBHub 的正则 SQL limiter：本地词法扫描保留 `WITH` 查询，忽略字符串/注释/嵌套分页，并安全处理尾部分号与行注释。
8. 真实 8 引擎矩阵验证大结果截断、探测行、精确度元数据以及截断后的普通连接/事务复用。
9. 新增 `DB_MAX_RESPONSE_BYTES` 协议级硬上限，包装顺序覆盖授权拒绝、内置工具和外部插件工具；超限后保持 JSON/UTF-8 有效。
10. MongoDB `find`/`aggregate` 使用 `tryNext()` 逐文档读取，按 BSON 与 EJSON 较大值计费并在 `finally` 关闭游标。
11. 六个 SQL 驱动执行逐行字节预算；查询缓存键包含有效字节上限，避免跨预算复用。
12. SQL 词法守卫识别模式限定、引号及夹注释的危险函数调用，拒绝 PostgreSQL 服务器文件/外部连接/副作用函数、MySQL `LOAD_FILE` 等跨引擎高风险能力，并在 MCP 只读层和驱动写入层双重执行。
13. `connection_diagnose` 查询 PostgreSQL 当前角色、超级用户状态及三个服务器文件/程序预定义角色，结构化返回风险并提示使用最小权限账号；单测与真实 PostgreSQL/MySQL 矩阵覆盖已知绕过。
14. Redis 新增 `HSCAN`/`SSCAN`/`ZSCAN` MCP 工具，cursor 保持十进制字符串并返回续读位置；key、MATCH pattern 和 COUNT 均有输入边界。
15. `redis_get` 使用 `STRLEN` + `GETRANGE` 返回可续读字节窗口，不再先拉取完整大字符串；窗口切开 UTF-8 或包含二进制时返回 Base64，直接 driver `get` 与 pipeline GET/HGET 也执行字节预检。
16. `HGETALL`/`SMEMBERS`/`LRANGE`/`ZRANGE` 在 driver 层按 `DB_MAX_ROWS` 检查基数或实际范围；pipeline 禁止集合物化命令，不能绕过专用工具限制。
