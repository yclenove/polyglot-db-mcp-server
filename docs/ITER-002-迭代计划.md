## 4. 风险清单

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| F4 strict 行为变更导致已有用户依赖旧行为 | 中 | 高 | 新增 `strict-v2` 模式，保留 `strict` 向后兼容 |
| F8 HTTP 传输引入新依赖安全风险 | 低 | 中 | 使用 `@modelcontextprotocol/sdk` 内置实现，不引入新依赖 |
| 环形缓冲替换导致审计日志丢失 | 低 | 中 | 迁移前写入现有缓冲区快照；替换后增加数据完整性测试 |
| F5 导出大数据量审计日志时内存溢出 | 低 | 低 | 流式导出，限制单次导出条数 (默认 1000) |

## 5. 回滚方案

| 功能 | 回滚方式 | 耗时 |
|------|---------|------|
| F1-F2 | `git revert` 单独 commit | <1 min |
| F3 | 还原 `shift()` 调用，恢复原缓冲逻辑 | <2 min |
| F4 | 移除 `applyStrictMode` 中的值正则校验分支 | <2 min |
| F5-F6 | 移除工具注册 (`index.ts` 中删除导入) | <2 min |
| F8 | 移除 HTTP 传输启动分支，保留 stdio 默认 | <5 min |

> 所有回滚均为代码级操作，无数据库迁移，无状态依赖。
